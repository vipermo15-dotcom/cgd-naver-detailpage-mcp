STEP 00 직무 정렬 — 어디에 지원할 것인가 (신규)

같은 상세페이지 프로젝트라도 지원하는 직무에 따라 강조점이 완전히 달라진다. 먼저 목표를 정한다.

목표 직무 채용공고가 실제로 보는 것 이 프로젝트에서 강조할 부분
인하우스 커머스 디자이너 / MD 보조 매출·전환에 대한 이해, 플랫폼 규정 숙지 USP 도출 과정, 플랫폼별 규격 대응(예제 F), QA 꼼꼼함
에이전시 상세페이지 디자이너 다양한 브랜드 톤 소화력, 제작 속도, 비주얼 완성도 비주얼 디자인 시스템, 컴포넌트 재사용성, 여러 예제(A~D) 다양성
프리랜서 / 1인샵 기획부터 등록까지 혼자 끝내는 능력 전체 프로세스 완결성, AI/MCP 활용한 생산성, 카페24 HTML 퍼블리싱

하나만 고르지 않아도 된다 — 다만 포트폴리오 전체에서 "이 사람은 어떤 역할에 강한가"가 한눈에 읽혀야 한다. WORK 00(워크북)에서 정한 목표 직무를 이 문서 전체에 걸쳐 계속 참조한다.

STEP 01 주제 선정

좋은 주제:

  • 실제 상품
  • 브랜드가 명확한 상품
  • 이미지 자료가 충분한 상품
  • 구매자와 구매상황이 명확한 상품

피해야 할 주제:

  • 정보가 거의 없는 상품
  • 사실 확인이 어려운 상품
  • 과도하게 복잡한 상품군

STEP 03 AI 작업 로그 남기기

각 작업마다 다음 5개를 기록한다.

  1. 내가 해결하려던 문제
  2. Claude에게 준 입력
  3. Claude의 제안
  4. 내가 수정/거절한 이유
  5. 최종 의사결정

핵심은 "AI가 만들었다"가 아니라 "AI를 활용해 내가 어떤 디자인 의사결정을 했는가"이다.

STEP 03-B MCP 작업 로그 (신규, MCP 실습을 진행한 경우)

  1. MCP로 무엇을 자동화했는가 (예: 프레임 생성, 컴포넌트 스타일 읽기)
  2. Claude가 만든 결과 중 그대로 채택한 것
  3. Claude가 만든 결과 중 수정/거부한 것과 이유
  4. MCP 없이 수동으로 했다면 얼마나 더 걸렸을지 비교

이 로그가 중요한 이유: "AI 도구를 쓸 줄 안다"는 이제 기본값이다. 채용시장에서 차별화되는 지점은 "AI 결과를 비판적으로 검수하고 판단을 내렸다"는 증거다. STEP 03/03-B는 그 증거를 남기는 절차다.

STEP 06 포트폴리오 전체 구성 전략 (신규)

이 프로젝트 하나가 아니라 포트폴리오 전체 안에서 이 프로젝트가 어떤 역할을 하는지가 채용 담당자의 첫인상을 결정한다.

프로젝트 배치 순서

  • 상세페이지 프로젝트가 가장 강한 결과물이라면 1~2번째에 배치 (첫인상 승부)
  • 이미 더 강한 프로젝트(브랜딩/UI 등)가 있다면 "실무 즉시 투입 가능"을 증명하는 근거로 중간에 배치하고 첫 프로젝트에서 링크

다른 프로젝트와의 차별점 만들기

같은 교육과정 동기들과 포트폴리오가 겹치지 않으려면:

  • 상품 카테고리를 남들과 다르게 선택 (예제 A~D 중 겹치지 않는 것 우선)
  • 플랫폼 조합을 차별화(예제 F, 3플랫폼 대응은 이 과정 학생 대부분이 안 하는 지점)
  • MCP 실습 경험을 명시 — 아직 채용시장에 흔하지 않은 스킬

포트폴리오 표지/목차에 넣을 스킬 키워드

"상품 리서치 · UX 카피라이팅 · 정보설계 · Figma 컴포넌트 시스템 · Claude/MCP AI 협업 · 멀티플랫폼(네이버·쿠팡·카페24) 대응"

이 키워드 목록은 채용공고의 "우대사항"란과 매칭시켜 지원 직무마다 순서를 바꿔 강조한다(STEP 00 표 참고).

STEP 07 취업용 한 줄 설명

"Claude와 Figma MCP를 활용해 상품/구매자 분석과 상세페이지 콘텐츠 전략을 수립하고, 네이버·쿠팡·카페24 등 커머스 플랫폼 규칙에 맞춘 모바일 중심 상세페이지를 설계·제작했다."

(MCP나 멀티플랫폼을 실습하지 않았다면 해당 부분을 빼고 기존 문장을 사용한다 — 하지 않은 것을 과장하지 않는다.)

STEP 08 면접 설명법

질문: AI를 어떻게 사용했나요?

답변 구조: "Claude를 단순 이미지/카피 생성기로 사용하지 않고, 상품 분석 → USP → 콘텐츠 구조 → 카피 → QA의 단계별 보조 디렉터로 활용했습니다. 최종 판단과 디자인은 제가 수행했습니다."

질문: Figma MCP는 왜, 어떻게 썼나요? (신규)

"Claude가 Figma 파일의 기존 컴포넌트 스타일을 직접 읽고 카피를 반영한 프레임을 만들도록 했습니다. 다만 생성된 레이아웃 중 시선 흐름이 어색한 부분은 직접 수정했고, 그 판단 기준은 '첫 화면에서 가치제안이 보이는가'였습니다." — 도구 사용 여부보다 판단 기준을 언어화하는 게 핵심.

질문: 왜 여러 플랫폼 버전을 만들었나요? (신규)

"실무에서는 하나의 상품이 여러 채널에 동시에 등록되는 경우가 많다는 걸 알고, 같은 전략을 플랫폼별 규격과 사용자 흐름에 맞게 재구성하는 연습을 하고 싶었습니다."

질문: 디자인에서 가장 중요했던 점은?

"예쁜 화면보다 구매자가 어떤 순서로 정보를 이해하고 신뢰를 형성하는지를 먼저 설계했습니다."

질문: Figma에서 무엇을 했나요?

"모바일 프레임을 기준으로 정보 위계를 설계하고 Auto Layout과 컴포넌트로 반복 패턴을 관리했습니다."

STEP 09 채용공고 키워드 매칭 연습 (신규)

지원할 공고를 하나 골라 아래 표를 채운다.

공고에 쓰인 키워드/우대사항 이 프로젝트에서 대응하는 근거
(예: "스마트스토어 상세페이지 제작 경험") 5차시 전체 프로젝트, 네이버 규격 대응
(예: "AI 툴 활용 가능자") Claude 작업 로그, MCP 실습 로그
(예: "Figma 능숙자") 컴포넌트 시스템, Auto Layout 실습
(예: "다양한 채널 대응 경험") 예제 F 3플랫폼 대응

키워드가 매칭되지 않는 항목이 있다면 "부족하다"로 끝내지 말고, 자기소개서에서 "이 부분은 향후 어떻게 보완할 계획인지"로 전환한다.
