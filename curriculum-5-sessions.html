1차시 — 상품 분석과 상세페이지 전략

학습목표

  • 상품의 기능을 구매자 혜택으로 바꿀 수 있다.
  • 타깃 구매자와 구매 상황을 정의한다.
  • 경쟁 상품과 리뷰에서 구매 결정 요인을 찾는다.
  • 상세페이지의 핵심 메시지를 결정한다.
  • (신규) 이 프로젝트를 어떤 플랫폼 조합(네이버 단독 / +쿠팡 / +카페24)으로 포트폴리오화할지 방향을 정한다.

180분 운영

  1. 0~15분: 좋은 상세페이지와 나쁜 상세페이지 비교
  2. 15~20분: (신규) 플랫폼 선택 — WORK 00 작성 (08_플랫폼별_상세페이지_제작가이드.md 비교표 참고)
  3. 20~50분: 상품 정보 분해
  4. 50~80분: 경쟁/리뷰 분석
  5. 80~110분: 타깃과 구매 상황
  6. 110~140분: USP 도출
  7. 140~165분: 페이지 구조
  8. 165~180분: 발표 및 피드백

실습

샘플 상품: 잇포레스트 간편식/베이커리 제품 또는 강사가 제공하는 가상 상품

학생 작업:

  • 제품명 / 가격·옵션 / 핵심 기능 / 핵심 소재 / 사용 상황
  • 구매자 문제 / 구매 이유 / 경쟁 상품 / 차별점 / 증명 가능한 근거
  • (신규) 목표 플랫폼: 네이버 단독 / 네이버+쿠팡 / 네이버+쿠팡+카페24

Claude 프롬프트

"너는 커머스 상품기획자다. 아래 상품 정보를 분석해 구매자가 실제로 중요하게 생각하는 문제와 구매 이유를 도출하라. 기능을 나열하지 말고 기능→혜택→구매가치의 순서로 정리하라. 근거가 없는 표현은 별도로 표시하라."

트렌드 체크포인트

경쟁 상품 분석 시 "발견형 구매(트렌드5)"를 의식해 검색 상위 노출뿐 아니라 SNS/커뮤니티에 노출되는 방식까지 함께 관찰한다.

실무 팁

실무에서는 경쟁 분석을 한 번만 하지 않는다. 등록 직전에 다시 한번 확인해 최신 프로모션/카피 변화를 반영한다. (10_실무활용_팁.md #7 습관과 연결)

제출

01_product_research.md, 02_usp.md

2차시 — Claude 카피라이팅과 상세페이지 스토리

학습목표

  • 상세페이지의 정보 우선순위를 결정한다.
  • Hero부터 FAQ까지 스토리라인을 만든다.
  • AI 카피를 검수하고 브랜드에 맞게 수정한다.
  • (신규) 표시광고법·과장 표현 리스크를 스스로 걸러낸다.

180분 운영

  1. 0~25분: 상세페이지 스토리 구조
  2. 25~55분: Hero/Problem/Solution
  3. 55~90분: Benefit/Evidence
  4. 90~120분: Feature/How-to
  5. 120~145분: FAQ/CTA
  6. 145~165분: 카피 다듬기
  7. 165~180분: 카피 리뷰 + (신규) 표시광고 리스크 자가검수

핵심 공식

기능 → 사용 장면 → 사용자 혜택 → 증거 → 구매 이유

Claude 실습

  • 3개의 Hero 헤드라인 / 3개의 서브카피 / 장점 5개 / 섹션별 본문 / FAQ 5개
  • 과장 표현 탐지
  • (신규) "이 카피에서 법적으로 문제가 될 수 있는 표현을 찾아 근거와 함께 알려줘" 프롬프트 실습 (10_실무활용_팁.md #2 참고)

트렌드 체크포인트

Evidence 섹션 카피는 "UGC 톤(트렌드5)"을 실험 — 실사용자가 말하듯 짧고 구체적인 문장으로 1~2개 대안 카피를 만들어 비교한다. 단, 허위 후기 조작은 금지(워크북 WORK 06 규칙 유지).

실무 팁

카피는 "예쁘게"가 아니라 "CS 문의를 줄이는가"로 평가된다. FAQ를 쓰기 전 "이 상품을 살 때 가장 많이 물어볼 질문 5개"를 먼저 적어본다. (10_실무활용_팁.md #4)

3차시 — Figma 정보설계와 와이어프레임 (+ MCP 연동 1)

학습목표

  • 모바일 화면 기준으로 콘텐츠를 배치한다.
  • 섹션별 정보량을 조절한다.
  • Auto Layout과 컴포넌트 개념을 적용한다.
  • (신규) Claude-Figma MCP 연동으로 파일 구조를 Claude가 읽게 한다.

Figma 파일 구조

  • Page 01 Research
  • Page 02 Content
  • Page 03 Wireframe
  • Page 04 Design
  • Page 05 Export
  • Page 06 Portfolio
  • (신규) Page 07 Platform Adapt — 쿠팡/카페24 확장용 (선택)

실습

  1. 375px 모바일 기준 프레임 생성
  2. 섹션별 높이 결정
  3. 8pt 간격 시스템 적용
  4. H1/H2/Body/Caption 텍스트 스타일 구성
  5. 카드/아이콘/버튼/배지 컴포넌트 제작
  6. 전체 페이지 흐름 연결
  7. (신규, 선택) MCP 연동 실습: "Figma MCP로 지금 파일의 페이지 구조와 스타일을 읽어와줘" 요청 → 연결 확인. 무료 플랜은 호출 횟수가 제한되므로 이 단계에서는 읽기(Read) 확인만 하고, 실제 생성(Write)은 4차시로 미룬다. (07_Figma_MCP_연동_설치가이드.md)

트렌드 체크포인트

카페24 확장을 염두에 둔 학생은 이 단계에서 "인터랙티브 스크롤(트렌드2)" 트리거 지점을 와이어프레임에 미리 주석으로 표시해둔다.

실무 팁

레이어/프레임 이름을 Hero_Headline, Benefit_Card_01처럼 처음부터 규칙 있게 짓는다 — 나중에 정리하려면 배로 걸린다. (10_실무활용_팁.md #7)

4차시 — 비주얼 디자인 (+ MCP 연동 2)

학습목표

  • 브랜드에 맞는 색/타이포/이미지 시스템을 만든다.
  • 긴 상세페이지에서도 리듬과 위계를 유지한다.
  • 정보 전달을 방해하는 장식을 줄인다.
  • (신규) MCP로 Claude에게 실제 프레임 생성을 맡기고, 결과를 검수·수정한다.

디자인 체크

  • 첫 화면에서 상품과 가치가 보이는가?
  • 한 섹션에 메시지가 하나인가?
  • 제목과 본문의 대비가 충분한가?
  • 이미지가 카피를 반복하지 않고 보완하는가?
  • 모바일에서 글자가 너무 작지 않은가?
  • 숫자/단위/옵션이 정확한가?

실습

와이어프레임을 실제 디자인으로 전환하고 최소 8개 섹션을 완성한다.

(신규) MCP 생성 실습 (이번 학기 핵심 1회 호출로 운영):

Figma MCP로 "03 Wireframe" 페이지를 확인해줘.
기존 컴포넌트 스타일(폰트, 색상, 간격)을 그대로 써서
2차시에 만든 Hero 카피로 375px 모바일 프레임을 만들어줘.
만든 뒤 스크린샷으로 보여주고 모바일 가독성 문제를 알려줘.

Claude가 만든 결과를 학생이 그대로 쓰지 않고 최소 1곳 이상 수정 — 수정 이유를 워크북 WORK 09에 기록한다. "AI가 만들었다"가 아니라 "AI 제안 중 무엇을 왜 거부했는가"가 평가 포인트. (10_실무활용_팁.md #6)

트렌드 체크포인트

5차시 — 최종 제작·QA·포트폴리오·플랫폼 확장

학습목표

  • 실제 등록을 고려한 최종 상세페이지를 완성한다.
  • 모바일 기준으로 오류를 검수한다.
  • 작업 과정을 취업용 포트폴리오 케이스 스터디로 전환한다.
  • (신규) 1차시에 정한 플랫폼 조합에 따라 쿠팡/카페24 버전으로 확장한다.

180분 운영

  1. 0~25분: 최종 디자인 수정
  2. 25~50분: 모바일 QA ((신규) 짝 검수 — 실무 팁 #1 "MD 역할" 시뮬레이션)
  3. 50~75분: 정보 정확성 QA + 법적 표기 재확인
  4. 75~95분: 최종 이미지 export
  5. 95~130분: (신규, 선택) 플랫폼 확장 — 쿠팡(1000×3000px 분할) 또는 카페24(HTML) 버전 재구성
  6. 130~155분: 취업 포트폴리오 작성 (05_자기주도학습_포트폴리오_가이드.md STEP 01~08 전체 적용)
  7. 155~175분: 3분 발표
  8. 175~180분: 피드백

최종 발표 구조

문제 → 조사 → 전략 → 정보구조 → 디자인 → AI/MCP 활용 → 플랫폼 대응 → 결과 → 개선점

최종 제출

  • Figma 원본 (네이버 버전 필수, 쿠팡/카페24는 선택)
  • 최종 상세페이지 (플랫폼별 export)
  • Claude 작업 로그 (MCP 사용 기록 포함)
  • 취업용 포트폴리오 케이스 스터디 1건 (05_자기주도학습_포트폴리오_가이드.md 기준)

실무 팁

파일명에 버전을 남긴다 (product_detail_v01, v02). 포트폴리오에 "무엇을 왜 바꿨는가" 한 장을 넣으면 신입치고 드문 "지속 개선" 신호가 된다. (10_실무활용_팁.md #3)
